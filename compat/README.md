# Legacy compatibility checks

`compat/legacy` is an independent consumer module. Its generated files are
frozen output of gogo/protobuf v1.3.2 (b03c65e), generated with protoc 36.2.
Do not regenerate these fixtures while updating the generator or runtime.

Run `sh compat/check.sh` with protoc 3.21.8 or 36.2 on PATH. It checks two independent
paths: frozen generated code against the candidate runtime, and unchanged
schemas regenerated by the candidate generator. The root suite also covers
proto2 defaults, extensions, custom types, WKT and the existing plugin matrix.

The version helper accepts both historical three-component versions and modern
two-component versions. CI checks both compiler families.

The v1.3.2 golden generator tests require protoc-min-version and protoc-gen-gogo
on PATH; the script builds them before running the suite. The consumer uses
replace to keep original imports and avoid linking two runtime identities.
Historical integration tests run in a disposable GOPATH-shaped copy because
some resolve proto imports through relative paths. No source tests are skipped.
The historical `testdata/multi` goldens are ignored by the original repository.
`compat/golden/multi` freezes them using the original v1.3.2 generator; the
script copies those references into the disposable suite before testing.

`sh compat/check-optional.sh` checks optional through the production gogo and
gogofast generators. The fixtures cover every scalar, explicit empty bytes, real and synthetic
oneofs, JSON/text, Merge/Clone/Equal, and UTF-8 in reflection and fast paths.

`sh compat/check-entrypoints.sh` compiles and runs the presence tests separately
for gogo, gogofast, gogofaster, gogoslick and gogotypes, and compiles auxiliary
GoString output. It verifies diagnostics for unsupported extensions and gofast's
alternate runtime, plus the compile-time rejection of new feature code by the
unmodified v1.3.2 runtime. Custom auxiliary plugins must explicitly implement
SupportsProto3Optional before GeneratePlugin advertises that capability.

Proto3 optional currently requires the gogo runtime and default pointer-based
scalar representations. nullable=false, message casttype, non-bytes customtype, embedded fields,
face and union combinations are rejected for optional fields. Bytes customtype
and correctly typed standard mappings are supported with runtime Version11. Scalar/enum/bytes casttype mappings are validated separately by
`check-optional-mappings.sh`; see `optional/README.md` for the representation contract.
Existing proto2/proto3 configurations keep their historical behavior.
Editions reflection support is advertised as described below.

The Editions foundation adds protocol declarations from protobuf 36.2 while
retaining historical fields and defaults that newer upstream schemas removed.
`merge-protocol.py` merges only additions and is idempotent; it does not replace
the legacy schema wholesale. Bootstrap protocol code with the frozen v1.3.2
plugins using `regenerate-protocol.sh`. `regenerate-features.sh` uses protoc 36.2
to compile canonical feature defaults into a Go 1.15-compatible byte table.

`internal/semantics` resolves core defaults, allowed targets, fixed features and
lexical inheritance without rewriting raw descriptors. Extensions inherit their
declaration scope; structural presence is handled separately. `internal/fieldmeta`
has no generator, descriptor or runtime dependencies. The production gogo entrypoint now advertises Editions 2023 through 2026 after
validation of the reflection backend. Unsupported backend/extension combinations
continue to fail during generation.

The original randomized TestStdTypesGoString could emit an invalid `<nil>` Go
expression for nil time.Time pointers, reproducible on untouched v1.3.2 with
seed 11. A separate generator fix and regenerated fixture omit the absent field.
The deterministic regression test and check-gostring.sh verify both the fixture
and freshly generated code; the randomized test is neither skipped nor suppressed.

Generated snapshots compare Go syntax and decompressed descriptor bytes. This
ignores only comments, formatting and gzip representation, which vary between
Go toolchains. Field tags, declarations, function bodies and descriptor data
must match; frozen consumer files are still compiled without modification.

The protocol merge CLI formats its output with clang-format using Google style
and preserving comment text (`ReflowComments: false`). Set `CLANG_FORMAT` to
select the formatter binary; the checked-in protocol files use clang-format
21.1.8. Formatting does not change descriptor fields or defaults.

Proto formatting is checked in a separate CI job using the exact version in
`compat/proto-format-requirements.txt`. Install it in a Python virtual environment
and run `python3 compat/format-proto.py --check` to check, or omit `--check` to
format. `CLANG_FORMAT` can select the installed binary. The shared `.clang-format`
applies Google style without rewriting comment text. The check covers tracked
proto files added or modified since v1.3.2, plus untracked proto files locally;
`--base` selects another baseline when needed.

The Editions backend covers 2023 reflection output: explicit
and implicit presence, required fields, UTF-8 policy, packed/expanded primitives,
open/closed enums (including imported enum definitions), map unknowns, oneofs
and DELIMITED messages. `check-editions.sh` uses protoc 36.2 as an independent
binary/text oracle. Production capabilities are enabled in the final entrypoint layer.
Gogo extensions and unsupported explicit Go features currently produce
diagnostics rather than partial output.
Raw descriptor data is kept separately from the private lowered generator view.

Edition 2024 fixtures cover option-only dependencies and option retention.
Runtime-retained custom options remain in reflection data; source-retained
options do not leak into embedded descriptors. This generator keeps gogo's
Open Struct API across editions. Explicit API_OPEN and keeping enum prefixes
are accepted; explicit HYBRID/OPAQUE APIs and other unsupported Go features
produce errors. No modern Go runtime is imported by consumers.

Edition 2026 adds custom JSON enum spellings, including empty strings, aliases,
quotes, Unicode, repeated values and map values. The text-format enum registry
is unchanged. An isolated `compat/oracle` module pins the official Go development
commit 0c373ff94f296da8645fbc892f211083b695709e (v1.36.13-0.20261007182434-0c373ff94f29)
for two-way JSON/binary checks; it is not a dependency of the root runtime.
New 2026 files use the Version6 runtime assertion. The modern protocol merger
also adds missing disjoint official option extension ranges, including 998.

`sh compat/check-downstream.sh` validates fixed etcd raft v3.5.0 and CockroachDB
errors v1.8.1 consumers, then regenerates raft using the original/candidate gofast
entrypoints and repeats its complete package suite without application changes.
The nested module and extra CI job keep those dependencies out of the runtime.

`sh compat/check-conformance.sh` runs the modern upstream 36.2 suites in an
isolated module. See `conformance/README.md` for the pinned runner setup, exact
historical failure records, supported Edition scope and CI reports. This gate
detects new failures; its passing status does not claim full conformance.

`sh compat/check-wkt-metadata.sh` checks the additive Type/Enum/Api/Method
Editions metadata update. It regenerates only the two maintained WKT bindings,
compares all old schema declarations against v1.3.2 with an explicit whitelist,
and compiles frozen original WKT consumers against the candidate runtime. Those
consumers must retain unknown edition fields during binary roundtrips.

Regenerate these two bindings with `sh compat/regenerate-wkt-metadata.sh`; an
optional output directory allows snapshot checks without modifying the checkout.
`merge-protocol.py` accepts optional relative filenames for additive WKT source
updates. Existing declarations remain authoritative; Method's deprecation is
reviewed separately by the exact schema-delta check.

`sh compat/check-required.sh` generates independent proto2 and Edition 2023
consumers at required-field word boundaries. Protoc 3.21.8 checks proto2; 36.2
checks both. Wide generated files require runtime Version7 and must fail to
compile against the fixed pre-B02 runtime, which already supported Editions
but did not validate required fields beyond the first 64.

`sh compat/check-editions-plugins.sh` generates and compiles the safe auxiliary
plugin combinations for Editions 2023/2024/2026, including independent GoString
output. The matrix verifies explicit zero/empty presence, clone/equality/order,
randomized GoString syntax, raw feature retention and unsupported options.

`sh compat/check-editions-fast.sh` exercises Editions 2023/2024/2026 with gogo,
gogofast, gogofaster, gogoslick and gogotypes. The initial matrix covers all scalar
and repeated types, presence, UTF-8 VERIFY/NONE, packed/expanded enums, negative
enums, required fields, unknown/wrong-wire fields and malformed input. Fresh
fast bindings use Version9. Fast wire/size results are checked against the
reflection codec and the pinned official protoc binary/text oracle. The matrix
also covers map UTF-8 and closed-enum routing, message/oneof merging,
DELIMITED singular/repeated/oneof fields, imported proto2 enums, cross-file and
nested extensions, raw descriptors and combined auxiliary plugins. Group tags
must match; extension policy comes from its declaration. A pre-B05 runtime must
reject these bindings. Partial codec dependency configurations produce explicit
generation errors; generate referenced messages with matching codec and auxiliary helper methods.
Custom/cast/nullable and unsafe options remain outside the supported set.

The default reflection runtime still has the individually recorded conformance
limitations, including validating some lazy string extensions only when read.
The generated Editions extension path validates registered UTF-8 and wrong-wire
fields before storage. Historical proto2/proto3 acceptance is preserved.

`sh compat/check-modern.sh` runs the isolated C02 V2 snapshot experiment on
Go 1.23+. It verifies detached reflection/protojson/Any/extensions, all five
optional mapping backends and frozen real downstreams. Lossy representations,
unknown closed-enum reflection mismatches and MessageSet are explicitly rejected;
see `compat/modern/README.md`. The root runtime remains Go 1.15 without V2 imports.


Independent binary fuzz qualification across all five generators is described in
`compat/qualify/binary/README.md`. Native C++ 36.2 is the semantic oracle; official
Go v1.36.12 helps identify acceptance differences between reference parsers.
Historical generated bindings and root Go/module requirements remain separate.
